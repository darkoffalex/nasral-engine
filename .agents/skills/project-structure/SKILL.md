# Навигация по структуре проекта

## Основные каталоги
- `sources` — Основной код проекта
- `include` — Заголовочные файлы проекта и вспомогательные утилиты
- `content` — Ресурсы, используемые и загружаемые в runtime
- `bin` — Результат компиляции проекта

## Структура `content`
- `content/meshes` — 3D модели, геометрия
- `content/textures` — Текстуры
- `content/shaders` — Шейдеры разных типов (растеризация, экранные эффекты, RT)
- `content/scenes` — Конфигурационные файлы сцены
- `content/project.json` — Конфигурационный файл проекта

## Структура CMake проекта

В корне проекта находится файл `CMakeLists.txt`, который содержит основные настройки и зависимости проекта. Проект содержит 2 под-проекта:
- Библиотека движка (`sources/engine/CMakeLists.txt`)
- Sandbox приложение для тестирования и отладки (`sources/sandbox/CMakeLists.txt`)

Движок организован как OBJ библиотека.

## Структура исходного кода движка `sources/engine` и `include/nasral`

Каждый из каталогов `sources/engine` и `include/nasral` содержит подкаталоги, которые отвечают за различные подсистемы движка.
Каталог подсистемы движка обычно назван тремя буквами, и это наименование совпадает с пространством имен, в котором находится код подсистемы.

- `ecs` (`include/nasral/ecs`, `sources/engine/ecs`) — Подсистема управления Entity Component System
- `gfx` (`include/nasral/gfx`, `sources/engine/gfx`) — Подсистема рендеринга
- `evt` (`include/nasral/evt`, `sources/engine/evt`) — Подсистема событий
- `log` (`include/nasral/log`, `sources/engine/log`) — Логирование
- `inp` (`include/nasral/inp`, `sources/engine/inp`) — Подсистема ввода
- `res` (`include/nasral/res`, `sources/engine/res`) — Подсистема управления ресурсами
- `scn` (`include/nasral/scn`, `sources/engine/scn`) — Подсистема управления сценой
- `run` (`include/nasral/run`, `sources/engine/run`) — Подсистема управления runtime циклом
- `include/nasral/common` — Общие типы и объявления, которые могут быть использованы в разных подсистемах движка
- `include/engine.h`, `sources/engine/engine.cpp` — Корневой класс движка, управляющий временем жизни всех подсистем движка

## Общая структура подсистем движка

Каждая подсистема движка обычно соответствует следующей структуре:
- Основной класс управления подсистемы (`manager.h`, `manager.cpp`)
- Класс ECS системы для данной подсистемы движка (`system.h`, `system.cpp`)
- Описание ECS компонентов, область ответственности которых лежит в рамках конкретной подсистемы (`components.h`)
- Объявления и типы, связанные с конкретной подсистемой (`types.h`)
- Файлы View для обращения к нужным ECS сущностям, связанным с конкретной подсистемой (каталог `entities`)
- RAII объекты, которые могут создаваться в рамках конкретной подсистемы (каталог `objects`)

Не все подсистемы строго следуют этой структуре, так как некоторые подсистемы могут быть более простыми и не требовать всего этого, а некоторые, напротив, требуют дополнительных классов.

## Ключевые архитектурные моменты

- Каждая подсистема движка наследуется от `Subsystem` (из `include/nasral/common/subsystem.h`). Используется CRTP паттерн для реализации статического полиморфизма.
- Подсистема может быть инициализирована при помощи своей Config структуры. В итоге каждая подсистема владеет своей конфигурацией (метод config)
- Обычно структура конфигурации подсистемы описывается в файле `types.h` и называется Config.

## Структура исходного кода Sandbox приложения

В каталоге `sources/sandbox` есть следующие файлы и каталоги:
- `main.cpp` — Основной файл приложения (содержит точку входа)
- `utils` — Вспомогательные утилиты для работы с движком (некоторые классы наследуются от классов движка)
- `pch.h` — Предварительно скомпилированный заголовочный файл для ускорения компиляции
